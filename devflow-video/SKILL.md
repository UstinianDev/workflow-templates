# /devflow-video — AI 视频提示词生成工作流

**内置文件（渐进式披露，按需读，不默认全量进上下文）：**

| 类别 | 文件 | 何时读 |
|---|---|---|
| 核心规则 | `rules/core-rules.md` | **每次必读**：核心理论/四原则可执行规格/约束阈值 |
| 术语映射 | `references/term-mapping.md` | 步骤 2 口语→术语时 |
| 镜头词库 | `references/camera-vocab.md` | 需判断 zoom/dolly/景深/速度时 |
| 审美参数 | `references/aesthetic-params.md` | 命中 4.1 抽象词要拆参数时 |
| 时间戳法 | `references/timestamp-method.md` | 目标模型支持垫图、需控节奏时 |
| 主体一致性 | `references/chaining.md` | 分镜≥2段且贯穿同一主体时（尾帧→首帧垫图） |
| 角色一致性卡 | `references/character-card.md` | 贯穿**角色**主体（人/需固定长相）时：出角色卡（正脸/侧脸/3-4侧）作首帧参考图；物体主体走 chaining |
| 模型特化 | `references/model-matrix.md` | 仅当用户指定目标模型才用 |
| 风格模板 | `templates/` | **按需加载**，非每次必用。当前 `game-of-thrones-style.md`（权游片头，仅用户明确要权游类片头才引用） |
| few-shot 范例 | `rules/examples/` | 对照写法时（4 个：动作向 / 模板片头 / 情感短片 / 角色一致性卡） |

## 输入

- 用户给定的故事/需求描述（必填）
- 可选：风格模板名（如用户明确说"权游类片头" → 才加载 `templates/game-of-thrones-style.md`；**未明确提及模板时不加载**，只用方法论规则）
- 可选：目标模型（如 Pavo Agnes；未指定则按通用规则，时间戳/垫图相关开关保持保守）
- 可选：输出存储位置（用户指定目录 → 存那里；未指定 → 存到当前工作目录，即用户启动 Claude Code 所在文件夹）

## 六步流水线

### 步骤 1：需求对齐（grill-me / grilling）
- 调用 grilling，按 devflow 家族的"需求对齐模式"一次对齐全部事项，不留遗留到生成阶段：
  1. 故事逐句确认：主角、时间线节拍（几段、每段几秒）、情绪走向
  2. 冲突/缺口：需求与目标模型能力是否匹配（时间戳法、负面描述支持情况未知时，先按保守假设生成，并标注"该段依赖模型支持 X，若不支持请删除"）
  3. 多方案给推荐项
- **跳过门槛（客观四条，缺一不可）**：故事含 ①明确主角 ②明确时长（秒数）③明确风格/情绪基调 ④场景数 ≤2 且已描述清楚。四条全满足才允许跳过 grilling，缺任何一条都必须走完整对齐。跳过时须在输出中注明"已跳过对齐（四条门槛全满足）"。
- **热点/梗/近期事件的触发式检索（仅当信号词命中时执行，不是每必用）**：
  - 触发信号：故事里出现专名、年份、或明显超出通用题材的新梗/事件（如"某平台热梗""某热点事件""xx 梗"）
  - 检索目标：**该梗/事件的视觉锚点**（标志性画面、动作、场景、BGM 情绪），不是资讯综述——目的是把梗名拆成步骤 2 可提取的画面要素，避免提示词里出现"xx梗"这种模型看不懂的名词
  - 检索手段：`crw search "<梗名> 视频 画面"` + 按需 `npx @arabold/docs-mcp-server@latest search`（未建库先 `scrape`）
  - **检索不到**（信号词太新、无公开视觉资料）→ **不硬猜**，直接问用户要一段该梗的画面描述，作为要素提取输入

### 步骤 2：要素提取与映射
按 `rules/core-rules.md` 的要素表，从故事中逐段提取：
- 每段：[景别] [主体] [动作] [场景描述]（必填四项）
- 每段可选：[镜头视角] [构图] [镜头运动]（按约束竞争原则，单段硬约束 ≤ 3 个，多余的主动留空并说明理由）
- 全片：贯穿主体、风格关键词、光线词（从 core-rules 第五节选）
- 输出为结构化表格（段序号 / 时间区间 / 四要素 / 三可选要素 / 留空原因），供下一步填充
- **画面语言 → 电影术语映射**：故事里的口语化镜头描述必须查 `references/term-mapping.md`，转成标准电影术语后再进入提示词，不得直接用故事原话写镜头指令。映射表未覆盖的描述，按最接近的术语匹配并在自检记录里标注"映射依据：X"。
- **贯穿主体判定（角色 vs 物体）**：先判"贯穿主体"是**角色**（人/动物/需固定长相）还是**物体**（齿轮/建筑/车）。角色主体 → 步骤 4 走 `references/character-card.md` 出角色卡（五要素长相 + 正脸/侧脸/3-4 侧朝向）；物体主体 → 走 `references/chaining.md` 尾帧垫图。

### 步骤 3：Plan 分镜规划
- 把步骤 2 表格转成分镜脚本，确认时间戳切分合理（可按 Agent 工具调用 Plan 智能体，或自己结构化展开）
- **仅当用户明确要求权游类片头、已加载 `game-of-thrones-style.md` 时**，此步需把模板的 AUDIO 段时间轴与分镜时间轴对齐。裁剪/扩展规则（不临场发挥）：
  - **全片时长 > 模板 30s**：模板最后一段（26-30s 收尾钟声）固定放在全片结尾；模板中间段按画面实际节拍裁剪后循环使用，空缺的时间段用"silence / 环境底噪"占位并在输出中标注
  - **全片时长 < 模板 30s**：从 0s 开始截断，只保留与画面实际存在的分镜节拍对应的音频段，丢弃 30s 后多余的段
  - **对齐判定**：每个画面分镜段必须能对应到至少一个音频段（音频段可 1 对多，画面段不能无音频对应），错位即在输出里显式标注，不静默处理
- **主体一致性 chaining（≥2 段且贯穿同一主体时启用，读 `references/chaining.md`）**：在分镜表加一列"参考帧来源"，标注第 N 段尾帧 → 第 N+1 段首帧参考；单段或无贯穿主体不加此列

### 步骤 4：提示词生成（填空法）
- 逐段按三句话结构填空（`core-rules` 第二节），末尾加风格关键词行
- 若启用了时间戳法（读 `references/timestamp-method.md`）：时间段只写节拍+画面内容+时间描述词，画面锁定交给垫图（如目标模型支持首尾帧）
- 命中 4.1 抽象词要拆参数 → 查 `references/aesthetic-params.md`，不临场发挥
- **若启用 chaining（步骤 3 已标注）**：生成时每段首帧标注参考图来源（`chaining.md`）；目标模型未指定/未查证垫图支持时，在遗留风险里标"chaining 垫图支持未查证，若不支持 image-to-video 则主体一致性退化回纯文本约束"
- **若启用角色卡（步骤 2 判定贯穿主体为角色）**：出 `<项目名>/character-prompt.md`（角色卡：五要素长相锁死 + 正脸/侧脸/3-4 侧朝向）；画面段**首帧参考图 = 角色卡对应朝向**，长相一律写"见角色卡"不重复描述；目标模型未指定/未查证角色卡垫图支持时，遗留风险标"角色卡垫图支持未查证，若不支持则角色一致性退化回纯文本（长相描述+一致性约束）"。角色卡是 chaining 的首帧参考图规范来源（`character-card.md`）
- **模板挂接位置（仅当已加载模板时）**：
  - 权游模板是**全片级 AUDIO 段**，不并入单个画面镜头段。生成物输出时，画面提示词（分镜拼接）与音频提示词（权游模板，按步骤 3 裁剪后的结果）**分列两段**，不做文字级合并
  - 模板中已写清的画面定调词（如 `Ultra-detailed miniature craftsmanship...`）可单独作为"全片风格关键词行"并入画面提示词末尾，其余画面细节不重复描述（避免过度指定）

### 步骤 5：四条原则自检
**执行主体**：总指挥直接执行（不另派 agent，控制多智能体成本），判断依据是 `core-rules` 第四节的**可执行规格**（不是临场发挥）：
1. **具体性**：扫描全文，命中 4.1 抽象词黑名单（破碎记忆/史诗感/孤独感/压抑/震撼 等）→ 逐条改写为可见画面（拆法查 `aesthetic-params.md`），列出改写前后对照
2. **非矛盾**：检查互斥词对共现（4.2），命中即修正
3. **正面描述**：扫描"不要/别/避免/无/no/without"，命中后先查**白名单**（4.3，如"无风"等合法词），白名单外的全部改成正面表述
4. **不过度指定**：按 4.4 判定——"段"指**时间戳段**（一个时间段块），单段内：
   - 硬约束（景别/视角/构图/运动）>3 个 → 删减到 ≤3，删减理由写入输出
   - 视觉属性词（颜色+材质+方位+光效，各自去重后计数）>6 个 → 触发删减告警

自检结果以"✅/❌ + 修正内容"形式附在最终输出末尾，并**单独落盘**为 `<输出目录>/<项目名>/自检记录.md`。

### 步骤 6：结构化输出（含落盘）
**内存中**最终交付格式：
```
## 分镜脚本
（步骤2的表格 + 步骤3的时间轴对齐说明）

## 画面提示词
（可直接复制粘贴进 AI 视频工具的整段文本；若启用模板，模板音频段不在此处，单独列在下方）

## 音频提示词（仅当已加载模板时）
（裁剪后的模板 AUDIO 段，标注了时间轴对齐说明）

## 自检记录
（步骤5的四原则对照结果）

## 遗留风险
（时间戳法对目标模型的支持性标注、留空项提示、垫图需求说明等）
```

**落盘（.md 格式，按模块分文件夹）**：
- 存储根目录：用户指定路径；未指定 → 当前工作目录（用户启动 Claude Code 的位置）
- 根目录下建 `<项目名>/` 文件夹（项目名 = 步骤 1 对齐时确定的 slug，短横线小写英文，如 `mars-base-escape`；未对齐跳过时也须先定名再落盘）
- `<项目名>/` 下按模块分子文件夹，每个生成物落一个 .md 文件：
  - `storyboard.md` — 分镜脚本（步骤 2 表格 + 步骤 3 时间轴对齐）
  - `visual-prompt.md` — 画面提示词（可直接粘贴）
  - `audio-prompt.md` — 音频提示词（仅加载模板时生成此文件）
  - `character-prompt.md` — 角色一致性卡（**仅当步骤 2 判定贯穿主体为角色且启用角色卡时生成**，含五要素长相+朝向清单）
  - `self-check.md` — 自检记录
  - `risks.md` — 遗留风险
  - `verification.md` — 出片对照回修记录（**仅当走了步骤 7 才生成此文件**）
- 每个 .md 文件顶部加 YAML frontmatter：`project`、`module`、`generated_at`、`target_model`（如未指定填"通用"）、`template`（如加载了模板填模板名，否则填"无"）
- 落盘完成后，输出里附上每个文件的绝对路径，方便用户直接定位

### 步骤 7：出片对照回修（仅当用户回传出片结果时触发）
- **触发**：用户回传某项目的出片结果（抽帧截图路径 或 出片视频路径）。无回传则不触发，保持前六步不变
- **诚实边界**：验证依赖**用户回传**，工作流**不**主动调用任何视频生成工具出片
- **对照判据**（逐项，复用已有规则非新造）：每个分镜段 → 对应出片抽帧，检查 ①主体是否贯穿（一致性）②景别/运镜是否对上 ③动作是否发生 ④光线/色调是否命中 aesthetic-params 目标参数
- **偏差分三类记录**：
  - **推测层偏差**（aesthetic-params 拆出的参数没对上 / 术语映射选词模型没响应）→ 进**回写队列**
  - **硬规则偏差**（四原则/阈值本身错）→ **只记录、不回写**，标注"疑似硬规则问题，需人工评审 core-rules"
  - **模型能力偏差**（某措辞该模型就是不响应）→ 记录到 `model-matrix.md` 对应模型条目，无来源标"实测：该模型不响应 X"
- **回写动作（仅推测层）**：
  - `aesthetic-params.md`：把"未对上"的参数行改为实测有效的替代参数，来源标注 `实测（<项目名>出片 <日期>）`
  - `term-mapping.md`：把"模型没响应"的口语→术语映射改为该模型实际响应的写法，同上来源标注
- **留证**：`<项目名>/` 落 `verification.md`（新落盘模块）：逐项对照表 + 回写清单 + 未回写项（硬规则/模型能力）说明；frontmatter 含 `project / module: verification / generated_at / target_model / 出片来源`
- **收敛判据**：本轮回写后新增要素在结果中清晰出现且前轮未退化（复用 `core-rules` 第七节），否则再出一轮

## 约束

- 本工作流只产出提示词文本，不直接调用任何视频生成工具（用户自述会用专门的 AI 视频工具制作图生视频/文生视频）。
- 每次运行前先读 `rules/core-rules.md`；词库/映射表/审美表/时间戳/模型特化按需读对应 `references/`；仅当明确要求权游类片头时才读模板。不靠记忆里的旧版本。
- 模板目录可无限扩展：新增风格时按"一个 .md 文件 + 顶部注释写明来源和适用场景"的格式放入 `templates/`。
- **落盘前若目标目录已存在同名文件，不覆盖，改为加序号后缀（如 `visual-prompt-2.md`）并在输出里说明。**
