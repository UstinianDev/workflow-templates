# /devflow-refactor — 重构工作流（devflow 家族·重构变体）

先读取 `~/.claude/skills/devflow-core/SKILL.md` 获取公共骨架（角色与约束、命名约定、阶段 0 分级与分类、阶段 1 需求对齐、阶段 2 规划与调研、阶段 3 并行、阶段 6~8、Gate 规则、档位传递与 TDD 三档），再按下述差异执行。

## 差异点

### 阶段 0（分级，启动先判断）

- 复用 core 阶段 0：先分类（重构/优化），再跨模块判断，定档 S/M/L。
- **S（轻量重构）**：单文件/单模块、无行为变化 → 跑通现有测试作基线 → 小步重构 → 轻量测试 → 交付核对。跳过：技术调研、并行执行、完整 code-review、`code-refactor-master` 全流程。
- **M（标准重构）**：1~3 模块 → 完整阶段，重构用 standard 强度，调研仅当方案不确定时。
- **L（重型重构）**：跨模块/涉数据与 API → 全部阶段，强制调研，L 级重构强度。

### 阶段 2 补充（技术调研）

- L 级强制、M 级按需、S 级跳过。用 **Firecrawl 搜索**重构模式/最佳实践 → **Context7 查询**备选方案当前文档 → 对比推荐写入计划（见 core 阶段 2.0）。

### 阶段 4（重构，按档）

- **先建测试基线**：用 `testing-quality-agent` 为目标模块补齐测试并全绿（无测试则先写，有测试则先跑通），确保重构不改变外部行为。
- **S 级**：不调用 `code-refactor-master`，直接小步重构（一次一种改动 → 每步跑测试）→ 保持行为不变。
- **M/L 级**：对每个子智能体的模块执行 `code-refactor-master`（精简版，已支持档位）：
  一次只做一种重构 → 每步跑测试 → 保持行为不变、向后兼容 → 消除坏味道（重复、长方法、大类别、深度嵌套、过长参数表）。
- 记录重构报告 `docs/refactor/<task>.refactor.md`（前后对比、应用的模式、每步测试结果）。

### 阶段 5（代码审查，按档）

- **L/M 级**：用内置 `/code-review` 审查当前工作区 diff（`/review` **仅当**存在可审查的 PR 时使用；两者均为 Claude Code 内置命令，本机无对应 skill 文件，不可用时回退为手动审查要点）。
- **S 级**：跳过独立审查，交付阶段核对即可。
- 审查发现的问题修复后，再进入公共阶段 6（`testing-quality-agent` 全量测试）。
