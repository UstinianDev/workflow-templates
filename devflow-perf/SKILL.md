# /devflow-perf — 性能优化工作流

> devflow 家族第四个变体。公共骨架规则见 devflow-base，本文件只写差异点。

## 铁律

1. 每一模块的细分功能严格不可改变，仅作性能优化
2. 核心目标：执行速度 > 可读性 > 质量
3. 必须输出修改前后执行速度数据对比表格
4. 行为不变：相同输入 → 相同输出

## Phase 0: 分级 + 自动瓶颈扫描

### 0.1 任务分级（直接内嵌，不读 devflow-base）

按 ①类型 → ②影响面 → ③工时 三级判断：
- 类型：优化类（不走 Bug 短路径）
- 跨模块：同一持久化资源多写入入口、状态跨 API/缓存传播 → 跨模块
- 定档：S ≤30 分钟·单模块 | M 半天内·1~3 模块 | L 跨模块·多天
- S 跳过拷问/调研/并行，L 全阶段+强制调研
- 有疑问再问用户，能判断的不问

### 0.2 自动瓶颈扫描

```
读目标目录 → 识别技术栈 → 按需加载规则库 → 逐文件扫描 → 排序输出瓶颈报告
```

- 技术栈识别：扫描 import/require/package.json/requirements.txt
- 规则加载：perf-rules-core（始终）+ perf-rules-frontend（前端）+ perf-rules-backend（后端）
- 扫描产出 → `docs/plan/<task>.bottleneck.md`（文件:行号 + 规则编号 + 严重程度）
- S 级只扫最严重的 1-2 个瓶颈

分级+瓶颈摘要 → `docs/plan/<task>.status.md`

## Phase 1: 需求对齐 — grill-me

- S 级：跳过，直接用瓶颈报告推进
- M/L 级：调用 grill-me，一次对齐优化范围 + 验收标准 + 风险
- 产出 → `docs/requirements/<task>.req.md`

---

## Phase 2: 规划 — Plan 智能体

- 输入：瓶颈报告 + 需求文档
- 输出：变更清单 + 优化顺序（高优先级先行）+ 预期提升 + 风险 + 验收标准
- **范围锁定**：变更清单中的文件列表即为白名单，Phase 4 不得修改清单外的任何文件
- L 级强制 `crw search` + `npx @arabold/docs-mcp-server@latest search` 技术调研
- 产出 → `docs/plan/<task>.plan.md`

---

## Phase 3: 并行执行 — agents

- 按计划拆分任务，创建项目级智能体并行派发
- 每个返回 `{完成项, 测试证据, 未完成项, 风险}`
- 跨模块并行，单模块串行

---

## Phase 4: 逐项优化 + 行为守护（非 TDD）

```
记录变更白名单（Phase 2 变更清单中的文件列表）
运行全量测试 → 检查 exit code → 非零则停下报告，不得继续
记录基线全绿状态

for each 瓶颈（按严重程度排序）:
  1. 执行优化（仅修改白名单内的文件）
  2. 运行回归测试 → 检查 exit code
     ├─ exit code = 0 → 继续
     └─ exit code ≠ 0 → 立即 git checkout 回滚该文件，不得继续优化该项
  3. 检查是否有白名单外文件被修改 → 有则回滚
  4. 中高风险项 → 补写边界测试（缓存过期/异步超时/空数据/并发）
  5. 记录变更 + 速度数据

运行性能基准 → 对比数据
```

**硬门禁（弱模型强约束）**：
- 回归测试必须用 Bash 工具执行，不得跳过
- exit code 必须检查，非零必须回滚，不得"尽力继续"
- 白名单外文件不得修改，发现即回滚
- 测试未全部通过不得声称优化完成

---

## Phase 5: /review（S 跳过）

重点：隐式行为变化、缓存一致性、异步错误、内存泄漏。

## Phase 5.5 模块连通性验证（M/L 级强制，S 级按需）

- 性能优化可能改变数据流路径（引入缓存层、批量处理、异步化、懒加载），导致模块间调用链断裂或行为漂移。
- 在 /review 修复后、全量测试前，执行公共骨架 **阶段 6.5 模块连通性验证**：
  1. 识别优化涉及的所有跨模块调用链（特别关注新增的缓存/异步路径）。
  2. 逐链验证：接口契约一致性、缓存命中/未命中时的数据格式、异步错误传播路径。
  3. 输出连通性报告 `docs/plan/<task>.connectivity.md`。
- 断裂链路必须修复后才能进入全量测试；优化不应以牺牲连通性为代价。

## Phase 8: 交付

输出：
1. 速度对比表格（必须）
2. 变更清单 + 剩余风险 + 未优化项
3. 测试证据

Gate（任一不满足则停下，不得声称完成）：
- 速度有提升 → 必须有数据证明
- 行为未变化 → 回归测试全绿
- 白名单内修改 → 无计划外文件变更
- 测试全通过 → exit code = 0
